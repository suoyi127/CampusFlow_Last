# 学习空间推荐系统三人开发计划

版本：1.0
制定日期：2026年10月9日
适用规模：三人课程大作业团队

本计划将工作拆成可独立开发和验收的任务，采用一个Spring Boot后端、按业务功能分工、前后端同一Git仓库。用户查询学习空间，服务器模拟签到和分贝检测，数据管理员维护空间与审核评价，服务器管理员管理账号、配置和模拟运行。

## 1 已确定的协作方式与排期基线

| 决策 | 已选择方案 | 实施方式 |
|---|---|---|
| C1A 模块形式 | 一个后端，按业务包划分 | auth、space、simulation、status、recommendation、review、system |
| C2A 分工方式 | 按功能分工 | 每个功能指定负责人，复杂模块用页面和接口分工平衡工作量 |
| C3A 仓库组织 | 单仓库 | frontend、backend、database、docs放在同一仓库 |

排期默认采用3周、15个工作日，每人每天约2至4小时，并假设已具备基本框架使用能力。日期以D1至D15表示，可从实际开工日顺延；这是排期目标，不是已确认的提交期限。若需要学习框架，可将每个阶段延长，保留阶段顺序和集成节点。

技术基线沿用上一版默认方案：Vue 3、TypeScript、Vite、Element Plus；Java 21、Spring Boot、Spring Security、MyBatis-Plus；MySQL。手机端按适配网页实现，PC管理员以表格操作为主。若课程要求微信小程序或独立App，需要调整前端和登录适配任务。

## 2 三人职责与工作量平衡

| 成员 | 主责 | 页面职责 | 后端职责 |
|---|---|---|---|
| A 用户与推荐 | 用户查询体验、推荐计算、前端公共基础 | 登录、空间列表、详情、我的评价；服务器管理页面 | 筛选、评分、排序、用户列表与详情的聚合接口 |
| B 空间与评价 | 业务数据管理、评价审核、数据库脚本协调 | 空间管理、评价审核、异常记录检查 | 空间资料、评价提交修改撤回、审核与均分 |
| C 权限与模拟 | 后端公共基础、实时数据、系统接口 | 提供各管理页面所需接口并配合联调 | 登录权限、账号配置、模拟到访、分贝采样、状态汇总、日志 |

为了降低C的负担，登录页面和服务器管理页面由A实现；C交付对应接口。B的异常记录检查页面调用C提供的数据查询和有效性标记接口。A的评价表单调用B的接口。

每人负责自己的模块测试、错误修复和操作说明。B协调数据库脚本和合并排期，但不代替其他成员修复业务代码。代码审查默认轮换：A的PR由C审查，B的PR由A审查，C的PR由B审查；公共接口变更需相关调用方参加。

## 3 模块和数据归属

| 模块与负责人 | 数据归属 | 对外提供的能力 |
|---|---|---|
| auth与system — C | sys_user、system_config、audit_log | 当前账号、角色校验、账号管理、配置、日志写入与查询 |
| space — B | study_space | 查询空间基础资料、编辑设施与开放时间、停用恢复 |
| simulation与status — C | simulation_run、sim_visit、noise_device、noise_sample、space_snapshot | 模拟控制、最新状态、原始记录检查、异常标记与恢复 |
| recommendation — A | 不维护其他模块原始表 | 聚合空间资料与状态、筛选排序、推荐理由 |
| review — B | space_review | 用户评价、审核、公开评价与均分 |

数据库表的业务变更由拥有该表的成员提交。B负责检查命名、关联和初始化脚本，不代写全部表。各成员使用独立本地数据库，按同一组版本化SQL脚本初始化；已合并脚本不改写，后续变更新增脚本。

跨模块通过Service的公开方法或查询接口访问。A不直接调用C的快照Mapper，C不直接修改B的空间表。公共目录只放错误结构、分页格式、时间处理等通用内容，不放具体业务规则。

## 4 最先交付的接口约定

D2结束前确定以下约定，先提供请求和响应示例。页面可以用这些示例开发，D5开始接真实接口。

| 接口或内部能力 | 提供方 | 调用方 | 交付节点 |
|---|---|---|---|
| 登录、退出、当前账号 | C | A及全部管理页面 | D2约定，D5可运行 |
| 空间资料查询与维护 | B | A、C、B管理页面 | D2约定，D5可运行 |
| 最新空间状态批量查询 | C | A | D2约定，D5可运行 |
| 用户列表与详情聚合接口 | A | A用户页面 | D2约定，D5可展示，D8完成排序 |
| 评价提交修改撤回与公开评价 | B | A | D2约定，D8可运行 |
| 评价审核 | B | B审核页面 | D2约定，D11完整 |
| 实时记录查询与异常标记 | C | B | D2约定，D11完整 |
| 账号、配置、模拟控制、日志 | C | A服务器管理页面 | D2约定，D11完整 |

统一规则：编号和枚举类型固定；距离单位为米；拥挤率为0至1；时间包含时区；缺失数据使用null和状态字段；分页格式统一；未登录返回401，无权限返回403。评价所属用户和所有管理权限由服务器验证。

实时状态至少返回spaceId、simulationRunId、snapshotVersion、currentPeople、capacity、occupancyRate、noiseDb、quietLevel、人数状态、噪声状态及各自更新时间。人数和噪声不能共用一个含义模糊的更新时间。

接口说明保存到docs/contracts。Java DTO和TypeScript类型分别实现，但必须遵守同一约定。接口变更在同一PR中更新说明、示例和已受影响的调用方；不临时改名而不通知其他成员。

## 5 三周阶段安排

| 时间 | A的任务 | B的任务 | C的任务 | 共同验收 |
|---|---|---|---|---|
| D1至D2 公共基础 | 前端启动、路由、请求封装、登录布局；确认推荐入参和返回值 | 空间及评价表、初始化空间；协调数据库脚本与接口文档 | 后端启动、公共错误格式、权限结构；账号与模拟表定义 | 每人可启动项目；三角色和10个空间的初始化方案固定；接口样例完整 |
| D3至D5 第一次集成 | 用户列表详情、管理导航；接登录与空间状态接口 | 空间新增编辑停用、空间管理页面、基础查询Service | 三角色登录、最小权限检查、人数与噪声定时生成、状态接口 | 用户登录后看到真实空间及动态状态；手机与PC读取同一服务器 |
| D6至D8 核心业务 | 硬条件筛选、综合和单指标排序、理由；评价表单与我的评价 | 评价提交修改撤回、公开评价均分、待审核队列 | 虚拟签到签退完整生命周期、噪声窗口与过期状态、场景切换 | 噪声或人数变化后排序变化；用户评价进入待审核 |
| D9至D11 管理闭环 | 账号、配置、模拟控制和日志页面；完成全部接口接入 | 审核通过驳回撤销、异常检查页面、空间管理校验 | 账号禁用、配置校验、暂停重置、设备离线、异常记录标记、日志 | 三类角色全部流程贯通，权限和数据失效规则生效 |
| D12至D13 修复与验收 | 修复移动布局、排序与页面刷新；前端构建检查 | 修复评价状态和均分；验证数据库从空库初始化 | 修复权限、模拟边界、状态时效；后端关键测试 | 验收清单全部执行；不新增功能；失败项有负责人 |
| D14至D15 打包与演练 | 前端构建并交接静态文件；用户演示说明 | 核对初始化及演示数据；整理操作说明与验收记录 | 打包JAR和启动配置；系统与模拟演示说明 | 在另一台电脑按说明启动；三人各展示自己的模块；保留修复缓冲 |

每天结束前至少同步一次进展。D5、D8、D11必须进行联合演示，不能只报告“代码已写完”。若D5未通过，优先修复登录、空间查询和动态状态，再推进下一阶段。

## 6 可直接分配的开发任务

### A 用户端与推荐

- [ ] A01 前端基础：登录布局、角色导航、请求封装、错误提示、移动适配骨架。D2完成；后端不可用时也能用约定示例浏览页面。
- [ ] A02 列表详情：聚合B的空间资料、C的状态和B的评价均分。D5完成基础展示；请求失败保留条件。
- [ ] A03 筛选排序：距离、设施、营业时间和实时阈值筛选；固定权重综合排序、单指标排序、同分顺序。D8完成，并提供已知样本的预期排序。
- [ ] A04 用户评价页面：提交两项评分、修改撤回、审核结果。D8完成，调用B的接口，不在前端伪造通过状态。
- [ ] A05 服务器管理员页面：账号表格、配置、场景选择、暂停重置、日志列表。D11完成，调用C的接口。
- [ ] A06 页面与交付验证：轮询取消、条件保留、离线过期展示、前端构建、移动演示说明。D13验证，D14交付构建产物。

### B 空间与评价

- [ ] B01 数据基础：空间和评价表、容量设施营业时间字段、10个演示空间；统一SQL脚本顺序。D2完成表定义，D5可初始化。
- [ ] B02 空间业务：查询和维护Service、管理接口与页面。D5完成；停用后用户列表隐藏。
- [ ] B03 评价业务：一用户一空间一条当前评价，提交修改撤回、评分范围、公开评价与均分。D8完成。
- [ ] B04 审核业务：待审核列表、通过驳回、驳回原因、撤销通过；修改已通过评价后重新待审核。D11完成，并验证均分随状态变化。
- [ ] B05 实时数据检查页面：人数和噪声记录、异常标记与恢复、设备状态。D11完成，记录接口由C提供。
- [ ] B06 数据与验收：验证从空数据库执行脚本、保留账号评价的模拟重置、停用及容量边界；整理业务操作说明。D13验证，D14准备最终演示数据。

### C 权限与模拟

- [ ] C01 后端基础与登录：统一错误处理、会话认证、密码摘要、三角色校验、当前账号接口；为前端提供会话及CSRF接入说明。D2完成约定，D5可登录。
- [ ] C02 最小模拟：定时生成到访和噪声记录、人数快照、批量状态接口。D5完成；两个客户端不得各自生成随机状态。
- [ ] C03 完整状态规则：签到签退关联虚拟人员，人数不越界；近期噪声中位数、独立更新时间、过期与离线状态。D8完成。
- [ ] C04 账号与配置：创建禁用账号、分配角色、旧会话失效、周期权重等配置校验、日志Service与查询接口。D11完成。
- [ ] C05 模拟管理：固定种子场景、启动暂停重置、设备离线；原始记录查询、异常标记恢复；更新与重置互斥。D11完成。
- [ ] C06 验证与打包：权限回归、人数边界、数据失效、模拟重置测试；打包后端、配置样例、启动说明。D13验证，D14提供JAR。

## 7 默认业务规则与范围控制

核心规则沿用需求方案：用户不手动上报人数和噪声；用户环境设施评分在审核通过后公开；角色权限不自动继承；模拟虚拟人员与真实账号分开；空间停用采用逻辑状态。

默认模拟周期和轮询周期为5秒，最新记录超过30秒过期，噪声采用最近60秒有效读数中位数。综合排序权重为距离30%、安静30%、空闲25%、设施15%；评分按0至1归一化。评价均分独立展示，不进入第一版综合得分。无近期数据不能显示成安静或空闲。

若C进度落后，保留签到签退记录、容量约束、固定场景、过期离线和权限，简化每个场景的参数配置界面；不得直接改为各前端随机生成状态。A和B优先通过既定接口示例开发页面，接口提供方按交付节点补齐实现。

第一版不增加图片上传、真实地图导航、短信注册、预约、学习时长统计、聊天、积分、微服务、消息队列或复杂推送。D11之后只修复缺陷和完成验收，不扩展功能。

## 8 协作与合并规则

1. main保持可构建；从main建立按功能命名的短分支，如feature/noise-simulation。
2. 每个PR完成一个可检查功能，包含验证步骤；有接口或数据库变更时同时提交对应说明与脚本。
3. 前端路由由各模块导出，公共入口汇总；公共请求和基础类型由A协调，权限公共配置由C协调，数据库脚本由B协调。
4. 合并前执行前端类型检查与构建、后端编译及相关关键测试；不要求大量重复实现细节的测试。
5. main上的问题由引入问题的模块负责人修复。发生合并冲突先确认业务含义，不直接采用“全部保留我的版本”。
6. 每日同步格式为：完成的任务编号、可演示结果、阻塞及需要哪个接口。接口阻塞当天说明，不等到集成日才反馈。

## 9 最终验收与交付

| 验收内容 | 主责 | 协作 |
|---|---|---|
| 三角色登录及越权拒绝、禁用账号会话失效 | C | A验证页面 |
| 空间维护、停用、设施和容量校验 | B | C验证模拟约束 |
| 手机与PC同一时点状态一致 | C | A验证展示 |
| 距离设施营业时间筛选、评分及稳定排序 | A | B与C提供样本数据 |
| 人数、噪声、离线和过期改变推荐结果 | A与C | B检查原始记录 |
| 提交审核、修改撤回与平均分变化 | B | A完成用户操作 |
| 标记异常后不参与汇总、恢复后重新计算 | C | B完成管理操作 |
| 暂停重置、日志保留、非法配置拒绝 | C | A验证管理界面 |
| 空库初始化、构建打包、另一台电脑启动 | 全员 | 分别验证自己负责部分 |

最终交付包括源代码、版本化SQL与初始化数据、前端构建产物和后端JAR、配置样例、启动说明、三类演示账号、验收记录及答辩演示步骤。密码、真实连接凭据不得写入仓库；演示账号使用明确标记的测试密码。

答辩流程：A展示筛选推荐；C切换人流与噪声场景，由A展示排序变化；A提交评价，B审核并展示均分变化；A与C展示设备离线、模拟控制、账号禁用和日志。三人分别解释模块边界、接口依赖及自己完成的验证。
